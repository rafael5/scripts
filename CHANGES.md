# CHANGES

## What this file is

A human-readable log of *why* things changed — intent, decisions, and context
that git diffs and commit messages can't capture on their own. Git records
what changed; this file records why it mattered.

It is not a substitute for commit messages, and not a changelog for end-users.
It is a personal maintenance journal for this repository.

## When to write an entry

- **After a meaningful work session** — one entry per session is enough, even
  if you made a dozen commits. Summarise what you were trying to do and what
  you decided.
- **When you make a non-obvious decision** — chose approach A over B, removed
  something intentionally, deferred something deliberately. Future you will
  not remember why.
- **When something broke and you fixed it** — what the symptom was, what
  caused it, how you resolved it.
- **Not required for** trivial edits (typo fixes, formatting), version bumps
  with no logic change, or anything fully self-explanatory from the commit
  message.

## Entry format

```
## YYYY-MM-DD — Short description of the session or change

What you were trying to accomplish, and any relevant context.

- Specific decision or action taken, and why
- What you tried that didn't work, if useful to record
- Anything left unfinished or deferred, and why

```

## Example entry

```
## 2025-11-14 — Switched package manager from pip to uv

Migrated the project tooling to uv after repeated environment reproducibility
issues with pip + venv across machines.

- Replaced requirements.txt with pyproject.toml managed by uv
- Kept requirements.txt as a lockfile export for compatibility with CI
- Decided NOT to pin transitive deps yet — too noisy, revisit if builds break
- Deferred moving to uv workspaces; overkill for now given single-package structure

```

## 2026-07-25 — Absorbed ~/claude; this repo is now the home-server repo

`~/claude` was a second home-server repo with a misleading name — it looked
like it owned Claude settings but contained none. The real Claude config is
`~/.claude/` (settings, skills, agents, hooks); the real home-server repo is
this one, which already carried `bin/`, the machine how-to guides, the hardware
report, and this journal. Two roots claiming one concern is the redundancy that
prompted the cleanup.

Absorbed here:

- `templates/{go,node,python}` — the project scaffolds `new-py-project` /
  `new-go-project` / `install-go.sh` copy from. Transferred with `git archive`
  so only tracked content moved (53 files, no build artifacts).
- `FILESYSTEM.md` — titled "Home Server Filesystem — Host: Linux Mint". It
  documents the machine, not Claude, so it belongs beside the other machine
  docs. It is now the single owner of the layout; `~/.claude/CLAUDE.md` keeps a
  short summary explicitly labelled as a projection of it. Previously both

  `CLAUDE.global.md` drift 238 lines before it was deleted on 2026-07-21.

  was the only place documenting `new-py-project`, `new-go-project` and
  `claude-status`. Those three scripts have lived in `bin/` undocumented.
- The two 2026-04-26 journal entries below, carried over verbatim.

Deliberately NOT carried (the archive at `git@github.com:rafael5/claude.git`
keeps the history):

- `GUIDE.md` — a guide to the folder being retired; its subject no longer
  exists. The live parts were salvaged as above.

## 2026-04-26 — New-project bootstrap, workspace status, memory compaction

Three workflow improvements landed in one pass after auditing where
session-start friction was highest.

- **`~/scripts/bin/new-py-project` + `new-go-project`** — collapse the
  ~8-step "starting a new project" recipe in FILESYSTEM.md into a single
  command. Both copy the template, rename the package across source/tests/
  pyproject.toml or go.mod/Makefile, init git with the standard
  `git@github.com:rafael5/<name>.git` remote, create `~/data/<name>/{input,
  output,db}` (Python default; Go opt-in via `--data`), wire the
  auto-memory symlink at `~/.claude/projects/-home-rafael-projects-<name>/memory`
  (this was the part most often forgotten by hand because the hash isn't
  predictable), and run `make install`. Flags: `--no-install`, `--no-remote`,
  `--no-data` (py) / `--data` (go). Smoke-tested with `--no-install
  --no-remote --no-data smoketest` then deleted; everything wired correctly
  including the memory symlink.
- **`~/scripts/bin/claude-status`** — one-screen orientation across every
  project under `~/projects/` (skipping `archive/`): branch, dirty count,
  ahead/behind vs origin, last commit, and a "current focus" line pulled
  from the matching `project_<name>.md` memory file. Read-only by default
  (no `git fetch`). `--write` also dumps `~/claude/STATUS.md` (added to
  `.gitignore` — regeneratable, not a source artifact). Two design choices
  worth recording: (1) the focus matcher tries `## Status / Current focus /
  Next / Setup status / Last session` headings before falling back to the
  YAML `description:`, so legacy memory files keep working; (2) the glob
  fallback (`project_<key>_*.md`) skips files "owned" by another project,
  which prevents `vista-docs` from showing focus pulled from
  `project_vista_docs_api.md`.
- **Compacted `project_fm_web.md`** from 224 → 88 lines by splitting
  phase-by-phase narrative into a new `project_fm_web_history.md` (152
  lines, on-demand). Always-loaded version now has the headline status
  ("Phases 0–5 done, phase 6 next") instead of a phase-0 commit hash from
  several sessions ago — which is why `claude-status` was previously
  returning a stale-looking focus line for fm-web. Updated MEMORY.md to
  point at both files with a "load on demand only" note next to the
  history file.
- **`project_ydb.md`** — closed out the historical "GitHub repo not yet
  created" / "gh CLI not installed" checkboxes (both done long ago) and
  added a 2026-04-26 status block noting Tier 1–3 dev tools shipped and
  parser work forked to `m-parser`. This unsticks `claude-status`'s focus
